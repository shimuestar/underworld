# HUD — 나침반 (2026-09-04)

## 역할과 자리

미니맵(오른쪽 위)은 "내가 어디에 있나", 나침반(상단 중앙)은 "저것이 어느 방향에 있나". 조준선에서 눈을 떼지 않고 위협·목표의 방향을
읽는 도구다. 항상 표시(토글 없음), 조작 없음 — 사용자 확정. 사망·클리어·상점/가방/스킬 창에서는 숨기고 실시간 루팅 중에는 보인다.

- 구현: `render/Compass.ts`(2D 캔버스, `#compass`, 360×46px, `position:fixed; top:8px; left:50%`). 왼쪽 위 안내 글(`#hud`)은 그 아래(top 62px).
- 데이터: `balance.hud.compass` — `arcDeg`(정면 ±60° 만 펼친다), 눈금 간격, `centerLabelDeg`, `edgeChevron`, `threat`(개수·거리별 크기),
  `loot`(반경·개수), `trapRadiusM`.
- 방위: 격자 -z 가 N. 방위각 θ(N=0, E=90)의 상대 방위 = θ + yaw. 표식의 상대 방위는 `bearingTo`(main 의 피격 마커와 같은 식, +는 오른쪽).

## 세로 배치 (46px)

방위 글자(y 7) · 눈금선(y 15, 15°마다 작은 눈금·45°마다 큰 눈금, 가운데를 초록 시선 바늘이 가로지른다) · 표식 두 줄(y 26/34 — 같은 자리에
겹치면 둘째 줄) · 거리 숫자·정면 이름표(y 41).

## 표식 (우선순위 순, 색은 미니맵 범례와 일치)

| 순위 | 표식 | 조건 | 모양 |
|---|---|---|---|
| 0 | 락온 대상 | `world.lockOnId` | 붉은 마름모(크게) |
| 1 | 위협 | 미니맵과 같은 규칙 — 시야(호+시야선) 안이거나 전투 추적 중(끝은 페이드). `Awareness.threatAlpha` | 붉은 점, `nearM`~`farM` 로 크기, `nearM` 안이면 숨 쉬는 고리. 가까운 것부터 `maxCount` |
| 2 | 피격 방향 | main 의 월드 고정 피격 마커(`hitMarks`) | 붉은 쐐기, 마커 수명 따라 옅어짐 |
| 3 | 소리 핑 | `Awareness.pings` (미니맵 핑과 같은 이벤트) | 잿빛 점, 1초 잦아듦 |
| 4 | 출구 / 제단 | 미니맵 안개로 **본 것만**(`Minimap.isRevealedAt`). 출구는 쇠창살이 열리면(`exitOpen`) 항상 | 녹색 X(봉인 중 붉은 쇠창살) / 금색 ■ + 거리 |
| 5 | 입구 계단 / 보물상자 | 입구는 `canAscend` 면 항상 · 상자는 본 것만, 빈 상자 제외 | 회색 ▲ / 호박색 ◇ + 거리 |
| 6 | 주머니 | `loot.radiusM` 안 미루팅 주머니, `maxCount` | 가죽색 ●(보스 금색, 내 주머니 파란색) |
| 7 | 함정 | 함정 감지 각인이 밝힌 것(`trap.revealed`) `trapRadiusM` 안 | 보라 ▲ |

- 띠 밖(|방위| > 60°)은 양 끝 화살촉으로만 — "뒤에 있다". 우선순위가 높은 것이 위에 그려진다.
- 정면 이름표 — 중앙 ±`centerLabelDeg` 안에 든 표식 중 우선순위 높은 것 하나만(목표는 거리도). 항상 이름을 쓰면 띠가 글자로 덮인다.

## Awareness — 미니맵과 나침반의 공용 기억

`render/Awareness.ts`: 전투 추적(`combat`: id → 만료 ms)과 소리 핑을 한 곳에 두고 `threatAlpha` 규칙도 여기 있다. `Minimap` 은 이를
받아 위임한다(`notifyCombat`/`ping` 은 예전 그대로 main 이 미니맵에 부른다). 층이 바뀌면 `reset`.

검증: 헤드리스 스크린샷 — 방위 글자·바늘, 왼쪽 주머니/오른쪽 위협(근접 고리), 뒤쪽 적의 끝 화살촉, 락온 시 중앙 이름표.
