## 1. 탄약

### 상한 규칙

각 탄종은 `weapons.*.ammoMax`를 가진다. 필드에서 획득하는 탄약은 상한을 넘지 못한다.
상한을 넉넉하게 잡고 싶은 충동이 들면 참을 것. **상한이 크면 저장 공간이 생기고, 저장 공간이 생기면 호딩이 발생하며, 호딩이 발생하면 이 게임의 코어 루프가 죽는다.**

### 제단 보급 — 폐지 (2026-08)

~~잔탄과 무관하게 상한으로 SET~~, ~~공격성 보너스 배율(최대 1.4배)~~ 모두 없앴다.
제단에 들어가도 탄약·수류탄이 저절로 차지 않는다. 전부 **골드로 산다** (§2 상점).

바뀐 결과를 분명히 해 둔다: 이제 **탄약을 아끼면 이득**이다. 원래 하드 룰의 정반대이며,
되살리려면 git 이력의 `Altar.aggressionMultiplier` 와 `enter()` 의 상한 SET 블록을 참조할 것.

### 오염탄

제단 밖에서 제작 가능. 재료는 필드에서 흔하게 드랍.

- 위력 `×0.6`, 명중 산포 증가
- 30발 사용마다 오염 +1 (`Corruption`에 누적 통보)
- **방어막 관통 불가** — `warden`류에게 무효

|---|---|---|

  골드·화살·탄약·수류탄·배터리는 예전처럼 자석. 음식은 HP·마나 **둘 중 하나만** 모자라도 먹는다.

## 2. 제단

### 상호작용 흐름

```
반경 안(altar.radius) + 제단을 바라봄(altar.facingArcDeg)
     → E → 진입: 세이브 + 오염 정산 + 보급 상점 UI
                  └─ Tab → 각인 교체 (제단에서만 해제 가능)
     └─ 우회 → 아무 일도 없음. altar_bypassed 계측만 남는다
```

- **시선 조건** — 가깝기만 해서는 안 되고 전방 `facingArcDeg`(기본 100°, 좌우 ±50°) 안에
  제단이 들어와야 `world.altarInView` 가 켜진다. 안내와 진입 모두 이 값을 본다.
  등지고 지나가는데 E 안내가 뜨는 게 거슬린다는 피드백에서 나왔다.
- **기둥은 막혀 있다** — `Level.props` 에 제단 기둥 발자국(1.1×1.1) AABB 가 들어가고
  `slideMove` 가 함께 검사한다. 셀 전체를 solid 로 두지 않은 이유: 그러면 반경 2.4 안에
  들어갈 수가 없다. 실측 — 정면 돌진 시 중심 0.95m(기둥 0.55 + 플레이어 0.4)에서 멈추고,
  옆으로 1.5m 비키면 그대로 통과한다.
- **부활 지점은 제단 중심이 아니라 진입할 때 서 있던 자리** — 중심으로 되살리면 기둥 안에
  파묻힌다.

### 안전실

제단은 **입구 하나짜리 막힌 방** 안에 있다 (z01_f1: 격자 행 10~11 × 열 19~23, 입구 [12,21]).
부활 지점이기도 해서, 되살아나자마자 전투가 붙으면 죽음의 고리에 빠진다.

- `altar.safeRadius`(10m) 안에는 **적을 아예 스폰하지 않는다** (`Spawner`). 레벨에 실수로
  가까이 배치해도 걸러지고, 몇 마리를 건너뛰었는지 콘솔에 남는다.
- 실측(부활 직후 3초): 살아 있는 적 44마리, 최근접 16.5m, **어그로 0 · 피격 0**.
- 벽이 시야를 끊는 게 핵심이다 — 반경만으로는 부족하고, 방이 닫혀 있어야 한다.

**제단은 강제 통과 지점이 아니다.** 레벨 설계상 반드시 우회로가 존재해야 하며, 우회 시 아무 페널티도 주지 않는다 (보급을 못 사는 것 자체가 대가다).

### 보급 상점

가격·회복량은 전부 `balance.altar.shop`. 기준은 **처치당 평균 골드 ≈ 3.9** (드랍률 0.65 × 3~9).

| 품목 | 효과 | 가격 | 재고 | 보유 상한 |
|---|---|---|---|---|
| 체력 회복 | +25 HP | 20 | 1 | `player.healthMax` |
| 마나 회복 | +35 마나 | 15 | 1 | `mana.max` |
| 권총탄 | +20발 | 12 | **3** | `weapons.pistol.ammoMax` |
| 수류탄 | +1개 | 25 | **2** | `weapons.grenade.ammoMax` |
| 예비 배터리 | +1개 | 20 | 1 | `altar.shop.battery.sparesMax` |

- **재고 소진 → 5분 재입고** (`altar.shop.cooldownTicks` = 18000틱). 품목별 `stock` 만큼
  연속으로 살 수 있고, 다 쓰면 타이머가 걸린다. 시간이 지나면 하나가 아니라 **가득** 찬다.
  품목별로 따로 돌며 다른 품목은 영향받지 않는다. 한 제단에서 물자를 통째로 쓸어 담지
  못하게 하는 장치다.
  UI가 열려 있는 동안은 시뮬레이션이 멈추므로 **상점에 서서 기다려도 줄지 않는다**.
- 이미 상한이면 **구매 자체가 막힌다** (`shop_denied { reason: 'full' }`) — 골드를 헛되이 쓰지 않게.
- 골드가 모자라도 같은 경로로 거절한다 (`reason: 'no_gold'`). 쿨타임 중이면 `'cooldown'` 이
  다른 두 사유보다 우선한다 (돈이 있어도 못 사는 진짜 이유가 그쪽이므로).
  어느 쪽이든 골드는 소모되지 않는다.
- 성공 시 `shop_purchased { item, price, amount, gold }`.
- **돈이 없어도 막히지 않는다** — 해머는 탄약을 쓰지 않는다. 무일푼이면 근접으로 싸우게 되는데,
  이건 부작용이 아니라 의도다.

확인 프롬프트에 현재 잔탄율을 표시한다. "9mm 42/60 보유 중" — 플레이어가 손해를 인지할 기회를 준다.

### 리스폰

진입한 제단이 리스폰 지점으로 등록된다. 사망 시:
- 위치·체력 복원
- 탄약 = 상한 (다시 보급된 것으로 처리)
- 마나 = 0
- 각인·오염 = 마지막 정산 상태 유지
- 우회했던 구간의 진행도는 초기화

## 3. 오염

### 누적과 정산

오염은 **대기값(pending)**과 **확정값(applied)**을 분리한다.

```ts
interface Corruption {
  applied: number;   // 몸에 반영된 값. 0~100
  pending: number;   // 아직 정산되지 않은 누적분
}
```

각인 부착, 오염탄 사용, 유틸 마법은 `pending`에 쌓인다. 제단 진입 시에만 `applied += pending; pending = 0`.

UI에는 두 값을 다르게 표시한다. `applied`는 실선, `pending`은 그 위의 반투명 예고 구간. 제단에 들어가면 어디까지 올라가는지 미리 보여야 선택이 성립한다.

### 임계값 처리

`applied`가 임계를 넘는 순간 `corruption_threshold` 이벤트를 발행하고 되돌리지 않는다.

| 임계 | 효과 |
|---|---|
| 25 | 벽 문자 해독 활성화 (`world.canReadGlyphs = true`) |
| 50 | 근접 위력 +25%, 총기 조작 페널티 |
| 75 | 일부 적 비적대화 |
| 90 | 재장전 중 총기 낙하 확률 발생 |

### 시각 변화

12.5 단위로 8단계. `applied` 변화 시 `render/HandModel.ts`에 단계 인덱스만 통보한다.
구조적 변화(모델 교체)는 단계 3/5/7에서, 나머지는 머티리얼 파라미터 보간으로 처리한다.

**슬라이스 범위** — 단계 0~2까지만 구현한다 (오염 25 도달 시점).

## 3.9 보물상자

`balance.chest`. 레벨에 놓인 상자 — **컨테이너**다(2026-09-04). E 로 뚜껑을 열면(1회 롤) 루팅 창이 열리고,
남긴 것은 그대로 있어 다시 뒤질 수 있다. 다 비우면 뚜껑 열린 채 남는다.

| | 값 |
|---|---|
| 상호작용 | 반경 2.4m + 상자를 보고 있어야 (제단과 같은 규약) |
| 골드 | 120~220 한 줄 — 가져가면 곧장 골드 |
| 각인 | **랜덤 1개** 한 줄 — 이미 가진 것은 빼고 뽑는다. 가져가는 순간 습득 |

- **획득하면 화면 가운데에 각인 색으로 크게 뜬다** (`#sigil-toast`, 2.8초).
  이름은 그 각인의 색이라 바닥에서 본 불빛과 이어지고, 아랫줄이 "눈에 새겨졌다" /
  "오른팔 슬롯이 차 있다 — Tab 에서 교체" 중 무엇인지 알려 준다.
- 전리품은 바닥에 흩뿌리지 않는다 — 주머니와 같은 루팅 창(`docs/systems/loot.md`)에서 가져간다.
  각인 줄을 가져가면 곧바로 몸에 새겨진다(§4). 창에서 바닥에 버릴 수도 있다.
- **부활해도 다시 잠기지 않는다** — 열었던 상자는 열린 채, 남긴 것도 그대로 (재롤 파밍 없음).
- 각인 풀은 **`slice: true` 를 먼저** 준다 — 이 빌드에서 실제로 효과가 도는 것들이다.
  그게 다 떨어지면 나머지에서 뽑고, 24종을 다 채웠으면 골드만 나온다.
- 골드 120~220 은 일반 적 드랍(3~9)의 20배쯤이다. 제단 기준으로 한 상자면
  회복·탄약·수류탄을 한 바퀴 산다.
- 몸으로 막는다 (`Level.addBlocker`). 창에서 바닥에 버린 것의 id 는 Loot 대역(1200000~)이다.
- 배치는 레벨의 `entities` 에 `{"type": "chest", "cell": [row, col]}`.
  1층에 3개 — 초입 오른쪽 방 구석 / **보스 방 탈출구 옆** / **균열 벽 뒤 막다른 방**
  (수류탄으로 뚫어야 들어갈 수 있다). 시작 지점 근처에는 두지 않는다 — 아무것도
  안 하고 받는 보상이 되어 버린다.

## 4. 각인

### 데이터 구조

```ts
interface Sigil {
  id: string;
  slot: 'eye' | 'rightArm' | 'leftArm' | 'heart' | 'spine';
  tier: 'passive' | 'small' | 'medium' | 'large';
  corruptionCost: number;
  color: string;   // #rrggbb — 24종 전부 다른 색
  effects: Record<string, number>;
}
```

부위별 슬롯은 각 1개. 최대 동시 부착 5개.

**색으로 구분한다.** 24종에 각기 다른 `color` 를 두고, 바닥에 떨어진 팔면체의
본체·발광·점광원과 각인 UI 의 견본이 같은 값을 쓴다(`sigilColor`) — 어둠 속에서
불빛 색만 보고 주우러 갈지 정할 수 있다. 랜턴 밖에서도 보이도록 너무 어두운 색은
쓰지 않는다 (휘도 하한을 테스트가 잠근다).

### 상태 3종

| 상태 | 효과 | 오염 |
|---|---|---|
| 미획득 | — | — |
| 소지 | **없음** | 없음 |
| 부착 | 효과 | 부착 시 1회 부과 |

각인은 주우면 곧바로 몸에 새겨진다 (2026-08). 슬롯이 차 있으면 인벤토리에 남는다.

### 부위 페널티 — 폐지 (2026-08)

부착 시 부위별 페널티(섬광 자해 / 재장전 −35% / 랜턴 −50% / 피격 마나 소실 /
산포 +40%)를 걸던 규칙을 없앴다. 각인은 **순수 강화**이고, 대가는 **오염 정산**으로만 치른다.
`balance.sigil.slotPenalty` 와 `Modifiers` 의 관련 필드도 함께 제거했다.

### 흉터

해제 시 `sigils.scars` 에 기록만 남는다. 페널티가 없어졌으므로 현재는 게임에 영향이 없고,
이후 다른 용도(제단 비용, 오염 가속 등)로 쓸 수 있게 남겨둔 자리다.

```ts
// 제거 시
scars[slot] = Math.max(scars[slot], penalty * 0.5);
```

`scars`는 누적 최댓값으로 관리한다. 같은 부위에 여러 번 부착/제거해도 흉터가 무한히 쌓이지는 않는다.

## 5. 계측 이벤트

```
ammo_spent        { type, amount }
altar_entered     { ammoLeftRatio, pendingCorruption, multiplier }
altar_bypassed    { ammoLeftRatio }
corruption_applied{ from, to, threshold?: number }
sigil_acquired    { id }
sigil_attached    { id, slot, corruptionCost }
sigil_detached    { id, slot }
pouch_dropped     { id, x, z, owner, tier, entries, merged }
loot_opened       { kind, id, entries, first? }      loot_closed { kind, id, emptied }
loot_taken        { kind, count, from, sigilId? }    loot_stashed { kind, count, to }
loot_dropped      { kind, count, from }              loot_denied { reason, kind }
pickup_bounced    { kind, x, z }
```

`altar_entered.ammoLeftRatio`의 평균이 **제단 도착 시 평균 잔탄율** 지표다. 목표 20% 이하이며, 50%를 넘으면 플레이어가 아직 호딩 습관을 못 버린 것이다. 그 경우 밸런스가 아니라 **초반에 탄약을 강제로 소진시키는 상황**을 레벨에 추가해야 한다.
