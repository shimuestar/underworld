## 1. 단일 반응 버튼

입력은 하나(**Space**)이며 상황에 따라 자동 분기한다.
**누르는 순간** 패링/반사/처형을 한 번 판정하고, 누르고 있는 동안은 방패 방어가
유지된다. Shift+Space는 회피.

입력 지연 개정 (2026-08): 예전에는 뗄 때 판정하고 방어는 12틱 홀드 후에야 켜져
체감 지연이 300ms를 넘었다. 지금은 판정도 방어도 누른 첫 틱(실측 1틱)이다.

조작 규약 (2026-08 개정): 좌클릭=원거리 무기(휠로 교체), 우클릭=근접 무기,
Space=반응. 무기는 근접·원거리 두 슬롯에 장착하며 숫자 키 전환은 폐기했다.

```
반응 입력 발생
  ├─ 반경 내 근접 공격이 활성 상태 → 패링 판정
  ├─ 반경 내 투사체가 접근 중     → 반사 판정
  ├─ 광역기 예고 중               → 회피 스텝
  └─ 아무것도 없음                → 회피 스텝 (기본값)
```

우선순위는 위에서부터. 두 조건이 동시 성립하면 근접 패링이 이긴다.

## 2. 적 공격 상태 머신

모든 근접 적은 이 상태를 가진다. 틱 수는 적별로 `entities.json`에서 로드.

| 상태 | 내용 | 반응 입력 시 |
|---|---|---|
| `idle` | 대기 | 회피 스텝 |
| `windup` | 예비 동작. 텔레그래프 발생 | **실패** — 경직 20t |
| `active_perfect` | 6t | 타격 이동 구간 앞절반 |
| `active_normal` | 12t | 타격 이동 구간 뒷절반 |
| `impact` | 타격 확정 | 피격 |
| `recover` | 후딜 | (아무 일 없음) |

`windup` 진입 시점에 이벤트를 발행한다. 오디오는 여기서, 시각 섬광은 `windup` 종료 4t 전에.

```
windup ──────────────► active_perfect(6t) ─► active_normal(12t) ─► impact
        ▲ 소리          ▲ 섬광            무기가 뻗어나가는 18t
```

### 패링 판정은 시간이 아니라 무기 끝 위치 (2026-08 개정)

`active_*` 두 상태는 이제 **무기가 뻗어나가는 18틱**을 둘로 나눈 것일 뿐이다.
완벽/일반은 상태가 아니라 **무기 끝과 가드의 거리**가 정한다.

```
tip(진행도) = 최대사거리 × (pullbackRatio + (1-pullbackRatio) × 진행도)
gap = 적까지 거리 - 플레이어 반경 - tip     (0 = 무기가 몸에 닿는 순간)

gap ≤ parrySpace.perfectBand → 완벽    (무기가 방패에 닿음)
gap ≤ parrySpace.guardDepth  → 일반    (가드 안까지 들어옴)
그보다 멀면                  → 헛손질  (경직 없음. 벌은 windup 조기 입력만)
```

최대사거리 = `attackRange × impactRangeMul` — impact 판정 거리와 같은 값이라
"닿으면 패링, 닿으면 피격"이 하나의 기하로 통일된다.

따라서 **멀리 있는 적일수록 무기가 도달하는 데 오래 걸려 패링 타이밍이 늦게 온다.**
개정 전에는 거리와 무관하게 "예비동작 종료 후 정확한 시간"에 눌러야 했고, 렌더는
4~5프레임 만에 무기를 다 뻗어 보이는 것과 판정이 어긋났다.

**렌더 규약** — `Stage`는 타격 구간에서 `enemy.weaponTipDist`를 그대로 반영한다
(보간 금지). 보이는 무기 끝 = 판정에 쓰이는 무기 끝.

## 3. 판정 결과

| 결과 | 피해 | 마나 | 추가 |
|---|---|---|---|
| 완벽 패링 | 무효 | `parry.perfect` × 배율 | 히트스톱 4t, 적 스태거 → 처형 가능 |
| 일반 패링 | 무효 | `parry.normal` × 배율 | 히트스톱 2t |
| 반사 | 무효 | `parry.deflect` × 배율 | 투사체 반전, 위력 ×1.5, 시전자에게 상태이상 |
| 회피 | 무적 8t | 0 | 이동 거리 `dodge.distance` |
| 실패 | 피격 | **축적 마나 × 0.5 소실** | 경직 20t, 배율 리셋 |

### 처형 (스태거 적에게 다시 반응 입력)

스태거 상태의 적에게 반응 버튼을 다시 누르면 즉사 처형이다. 연출 규약:

- 동작은 **해머 대각선 분쇄** — 어깨 뒤로 젖혔다 오른쪽 위에서 왼쪽 아래로 내려찍는다.
  (구 방패 강타는 폐기. 평타 3타의 정면 수직 강타와 구분되어야 한다)
- `reaction.executeFocusTicks` 동안 **모든 적이 완전히 멈춘다** — `Enemies.tick`이 통째로
  조기 반환한다. 마무리 동작이 온전히 보이는 시간을 확보하기 위한 것이다.
- 죽은 적의 **시각은 해머가 닿을 때까지 남는다** (`Stage.holdExecutionVictim`). 로직상
  즉사지만 즉시 지우면 허공을 치는 그림이 된다.
- 처형음·섬광·카메라 킥·사망 파편도 같은 접촉 시각으로 미룬다 (`main.ts`의 지연 연출 큐).
  접촉 시각은 `Stage.triggerExecuteFinisher()`가 ms로 돌려준다.

### 수호주술사 마법탄 — 내파 (implode)

착탄점에서 광역 **끌어당김**. 화염구(주황·팽창·밀어냄)와 정확히 반대로 잡았다 —
보라·수축·당김. 데이터는 `entities.json`의 `warden.attack.splash`.

| | 화염구 (플레이어) | 마법탄 (수호주술사) |
|---|---|---|
| 방향 | 폭심에서 **밀어냄** | 폭심으로 **끌어당김** |
| 광역 피해 | 30 (감쇠 0.3까지) | 12 (감쇠 0.35까지) |
| 부가 | 화상 DoT | 없음 — 이동 강제가 본체 |
| 색 | 주황, 팽창 | 보라, 수축 |

- **직격이면 밀린다, 빗나가면 끌린다.** 직격 밀림(`playerKnockback.magic` 2.8m/8t)이
  당김을 덮어쓴다. 즉 맞으면 뒤로 날아가 안전해지고, 피하면 폭심으로 끌려가
  근접 적의 사거리에 들어간다 — 회피가 완전한 해답이 아니게 만드는 장치다.
- **반사하면 적들이 뭉친다.** 되돌아간 탄이 시전자 앞에서 터지며 주변 적을 한곳으로
  모은다 → 화염구·해머 3타로 이어지는 광역 마무리. 반사가 이 적의 주 공략법인 만큼
  보상도 여기에 실었다. (실측: 폭심에서 2.1/3.3/3.8m 흩어져 있던 적 셋이 0.2/1.0/1.8m로 수렴)
- 광역 피해는 소유자 규칙을 따른다 — 적이 쏜 것이면 아군에게 `friendlyFireDamageMul`,
  반사된 것이면 전탄.
- **적 몸에 맞아도 똑같이 터진다.** 벽·바닥·적·플레이어 무엇에 닿든 광역이 난다
  (`implodeBolt`가 명중 판정보다 먼저 돈다 — 방패병 정면 방패에 막혀도 터진다).
  직격 대상은 본 피해만 받고 광역 피해에서는 빠지지만, 끌림은 함께 받는다.
- 끌리는 동안(`pullTicks`) 적은 다른 행동을 못 한다 — `Enemies.tick`의 넉백 분기가
  버티기·경직보다 우선해 early return 하기 때문. 당김을 늘리면 그만큼 굳는 시간도 는다.
- 보스는 끌려오지 않는다. 회피 무적 중인 플레이어는 면제.

### 방패병 정면 방패 — 언제 뚫리는가

`Entities.shieldBlocks` 가 공용 규칙이고, 투사체만 `shieldBlocksProjectile` 로 한 겹 더 연다.

| 상태 | 근접(해머) | 투사체(총·마법) |
|---|---|---|
| 평소 정면 | 막힘 | 막힘 |
| 스태거 | 뚫림 | 뚫림 |
| 방패 파괴됨 | 뚫림 | 뚫림 |
| **밀려나는 중 (`kbTicks > 0`)** | **막힘** | **뚫림** |

**폭발은 방패를 부순다.** 화염구·수류탄이 정면 방패에 걸리면 `shieldBroken` 이 되고,
그 폭발의 피해는 `shieldBreak.damageRatio` 배로 줄어든다 (방패가 충격을 먹는다).
등 뒤에서 터지면 방패와 무관하게 온전한 피해가 들어간다.

밀림 중 근접만 막는 이유: 벽에 붙어 밀려나지 못하는 방패병을 해머로 관통해 버리면
"해머는 방패병에게 HP 피해를 주지 않는다" 규칙이 깨진다. 실제로는 밀려난 적이 해머
사거리 밖이라 눈에 띄지 않는 차이다.

연출은 투사체 조건과 맞춘다 — `kbTicks > 0` 또는 스태거면 방패가 낮게·옆으로·뉘어져
내려가고(팔을 늘어뜨린 그림), **끝나는 순간 보간 없이 즉시 원위치**한다. 방어가 다시
켜지는 시점과 그림이 어긋나면 안 되기 때문.

> 판정 순서 주의: 폭발(화염구·내파)이 `kbTicks` 를 세우므로, 방패 판정은 폭발보다
> **먼저** 확정해 `applyProjectileHit` 에 넘긴다. 안 그러면 화염구가 자기 폭풍 때문에
> "가드 풀림"으로 오판해 방패를 못 깬다.

## 3.0 거미 — 검은 거미 / 흰 거미

둘을 같이 배치해야 의도한 압박이 나온다. **흰 거미가 묶고, 검은 거미가 달려든다.**

| | 검은 거미 (`spider_small`) | 흰 거미 (`spider_large`) |
|---|---|---|
| 색 | 검정 | 흰색 |
| HP / 속도 | 18 / 5.6 | 75 / 3.4 |
| 무게 | light — 해머 마무리에 잘 날아간다 | medium |
| 주 공격 | 근접 물기 (8) | **거미줄** — 피해 없음, 구속 |
| 특기 | **도약** 3.2~7m, 6.5m 를 날아간다 | `caster_kite` — 7m 안으로 붙으면 물러난다 |

- 도약은 족장 돌격과 같은 장치(`chargeRunTicks`)를 쓴다 — **예고 시점 좌표로만** 날아가므로
  옆으로 비키면 헛짚고 `whiffRecoverTicks`(75) 동안 굳는다.
- 흰 거미는 스스로 거의 아프게 하지 못한다. 위협은 **검은 거미를 위한 시간을 버는 것**이다.

### 거미줄 (`balance.web`)

| | 값 |
|---|---|
| 이동 속도 | ×0.42 |
| 벗기는 데 | 해머 **3타** (`breakSwings`) |
| 지속 | **없음 — 해머 말고는 안 풀린다** |

- **시간이 지나도, 아무리 움직여도 풀리지 않는다.** 해머로 걷어내는 것이 유일한 수단이라
  "묶였으니 무기를 바꿔 든다"는 선택을 강제한다.
- **방패로 막아도 들러붙는다** — 끈끈이는 막을 수 있는 게 아니다.
- 해머는 **적을 맞힐 필요가 없다** — 휘두르는 것만으로 한 겹씩 걷힌다.
- 한 대마다 `web_torn` — 눈앞에서 흰 실 조각이 찢겨 흩어지고(`Stage.spawnWebTear`)
  화면 막이 한 단계 옅어진다(3/3 → 2/3 → 1/3 → 0). 마지막 한 대는 `web_broken`.

## 3.0.5 족장 방어 규칙 — 완벽 패링만, 막기는 통하지 않는다

| 공격 | 패링 |
|---|---|
| 해머 지면 강타 | **가능 — 완벽만** |
| 돌격 내리찍기 | **가능 — 완벽만** |
| 바위 투척 / 화살 세례 | 불가 (회피·엄폐) |

- `perfectParryOnly` — 일반 대역(`guardDepth` 1.3)에서 눌러도 성립하지 않는다.
  무기 끝이 `perfectBand`(0.4) 안에 들어오는 순간만 받는다. 이르게 누른 입력은
  `parryBufferTicks` 동안 살아남아 대역에 들어오는 순간 성립하므로, 조금 이른 건 용서된다.
- **체력이 두 칸이다** — `health` 840 을 `healthBars`(2)로 나눠 420 짜리 두 칸으로
  보여 준다. 지금 깎이는 칸은 `healthBarState` 가 계산하고 HUD 와 이름표가 같은
  함수를 쓴다. 첫 칸(×2)은 보라, 마지막 칸(×1)은 잔량에 따라 초록→노랑→빨강.
- **처형 타격은 `executeDamage` 150** — 총량의 17.9%. 완벽 패링 3연속을 모아야 한 번
  나가는 기술이라 60(7%)은 대가로 초라했다. 처형만으로 잡으려면 완벽 패링 17번.
- **보스가 깨면 방이 함께 깬다** — 보스가 처음 플레이어를 알아채는 순간
  `enemyAi.bossAlertRadius`(45m) 안의 잠든 적이 전부 `chase` 로 넘어간다. 포효를
  듣는 것이므로 시야는 보지 않는다(벽 너머도 깬다). 실측: 1층에서 19마리가 함께 깬다.
- `blockCannotStagger` — **방패로 막아도 공격이 끊기지 않는다.** 칩 피해와 밀림은 그대로
  받고 플레이어만 굳는다(`clashPlayerStunTicks`). 방패 섬광·소리는 나지만 격돌 연출과
  적 튕김은 없다. 보스 앞에서 막기는 손해다 — 패링하거나 비켜야 한다.
- 보스는 완벽/일반 구분 없이 `parriesToStagger`(3) 연속이어야 스태거지만, 애초에
  완벽만 성립하므로 실질적으로 **완벽 3연속**이다.
- `parryAlwaysNormal` — 성립해도 **결과는 일반 패링**이다. 완벽만 받는 적에게
  완벽 보상까지 주면 매 패링이 최대 보상이 된다. 히트스톱 2틱, 마나 11,
  연쇄 상승 없음, 화면 문구는 "패링".

> **장갑(armored) 페이즈는 폐지(2026-08).** 스태거가 끝나면 장갑 껍질이 돋고 실탄으로
> 120을 깨야 패링 구간으로 돌아오는 2페이즈 순환이었다. 지금은 스태거 → 처형 →
> 후딜 → 다시 패링 3연속뿐이다. 되살리려면 git 이력의 `armoredAttack`·`armorHealth`·
> `phases` 와 `Enemies.staggered` 의 전환 블록, `Stage.armorPlates` 를 참조.

## 3.1 족장 거리별 행동

거리에 따라 셋 중 하나를 고른다 — 멀면 던지고, 중거리면 달려들고, 붙으면 해머다.

| 거리 | 행동 |
|---|---|
| ~3.4m (`attackRange`) | 해머 지면 강타 |
| 4.2 ~ 15m (`chargeAttack.minRange~maxRange`) | **돌격** — 달려와 내리찍는다 (재사용 5.5초) |
| 5m~ | 화살 세례 (재사용 10초) |
| 7m~ | 바위 투척 |

- **붙으면 던지기를 접는다** — `abortRange`(4.5) 안으로 들어오면 시전/연사를 끊고
  `attackMode`를 melee 로 돌린다. 연사는 남은 발수를 버리되 쿨다운은 그대로 문다.
  코앞에서 화살을 쏘고 있는 그림을 막는 장치다.
- 돌격은 `maxRange` 가 있는 공격만 거리로 발동한다 — 창병처럼 `wantsCharge` 로
  쓰는 쪽과 구분된다.
- **`chargeRunTicks` 가 있으면 예고 뒤 따로 달리는 구간(`charging`)이 생긴다.** 없으면
  타격 창(0.3초) 동안만 파고들어 3.8m 밖에 못 좁힌다 — 멀리서 쏘는 플레이어에게
  닿지 않던 원인. 족장은 72틱 × 13 = 15.6m 를 달린다.
  달리는 동안은 패링 대상이 아니고, 붙은 뒤에야 판정 창이 열린다.
  바닥 원도 함께 밀려와 위험 범위가 다가오는 게 보인다.
- **예비동작(0.57초)** — 스프린터처럼 웅크리고 앞으로 기울이며 무게를 뒤로 싣고,
  무기를 뒤아래로 끌어 내린다. 내리치기 예비동작(뒤로 젖히며 무기를 치켜듦)과
  정반대라 한눈에 갈린다. 발로 땅을 긁는 소리(`charge_ready`)가 함께 난다.
- **겨냥은 예고가 끝나는 순간 한 번뿐이다** (`chargeTargetX/Z`). 달리는 동안 플레이어를
  다시 보지 않으므로 옆으로 비키면 빈 자리를 친다. 추적하면 이동 회피가 성립하지 않는다.
  타격 창의 `chargeForward` 도 이 돌격에서는 건너뛴다 — 거기서 다시 쫓으면 같은 문제다.
  빗나가면 `whiffRecoverTicks`(100) 동안 굳어 반격 창이 열린다.
  실측: 가만히 서 있으면 2회 피격, 달리기 시작에 맞춰 옆으로 비키면 0회.
- **`aoeRadius` 는 `attackRange` 보다 커야 한다.** 달리기가 `attackRange`(3.4)에서
  멈추므로 반경이 3.0 이면 붙고도 헛친다 (실측으로 확인 → 4.2).
- **방패로 막아도 튕겨 나간다** — `blockedKnockbackMul` 1.0 / `blockedDamageRatio` 0.6.
  실측: 그냥 맞으면 30 피해 6.5m, 막아도 18 피해 6.5m. 몸으로 받는 기술이 아니라
  패링하거나 비켜야 한다. 크게 날리는 만큼 `playerKnockbackTicks`(20)로 늘려
  순간이동처럼 보이지 않게 한다.

## 3.2 족장 지면 강타 (aoeRadius)

`goblin_chieftain.attack.aoeRadius` 3.6. 해머로 땅을 내리쳐
**각과 무관한 원형 판정** — 옆으로 비켜도 소용없고 반경 밖으로 물러나야 한다.

- `attackReaches` 안에서 처리한다. `aoeRadius` 가 있으면 `arcDeg`·`impactRangeMul` 을
  건너뛰고 거리만 본다. **Reaction(패링)과 Enemies(피해)가 같은 함수를 쓰므로**
  "호 밖이라 못 막는데 원 안이라 맞는" 구멍이 생기지 않는다.
- 예고 중 바닥에 붉은 원이 그려진다(`aoeRing`). 화면 UI가 아니라 월드 바닥 표식이고,
  반경은 판정값 그대로다. 예고가 진행될수록 진해지고 내리치는 순간 가장 진하다.
- 내리치는 순간 `ground_slam` 을 발행한다 — **맞든 빗나가든** 땅은 울린다.
  main 이 충격음과 카메라 흔들림을 붙이고, 세기는 거리로 줄인다
  (실측 3m 1.80 / 8m 1.14 / 16m 0.45).

## 3.3 족장 화살 세례 (volleyAttack)

`goblin_chieftain.volleyAttack`. 예고 0.9초 → **0.5초 간격으로 10발**, 발당 12 피해.
재사용 10초, 최소 거리 5m. 쏘는 동안 제자리에 서서 **계속 조준**하므로 옆으로
움직여 흘려야 한다. 가만히 서서 다 맞으면 120 — 즉사다.

- `EnemyAttackDef.shots > 1` 이면 windup 종료 시 `volley` 상태로 들어가
  `shotIntervalTicks` 마다 한 발씩 쏜다. `shotIntervalTicks` 는 발사 틱을 뺀 대기값이라
  **29 = 실제 30틱(0.5초) 간격**.
- 화살은 `deflectable: false` → 반사 불가, 회피/엄폐 전용 (적색 텔레그래프 규약).
- 한 발이 약한 이유는 `attack.damage` 재정의 — `fireProjectile` 이 근접과 같은 규약으로
  `attack.damage ?? def.damage` 를 쓴다. (예전에는 def.damage 만 봐서 발당 30이었다)
- 예고는 UI가 아니라 **동작·발광·소리**로만 준다: 적색 텔레그래프 섬광 + 무기를 몸 앞으로
  가로질러 당기는 자세 + 시위 당기는 소리(`boss_volley_draw`) + "화살 세례 — 10발이 온다!".
  자세를 높이 치켜드는 안(팔 1.45rad)은 랜턴 조명 밖으로 나가 캄캄해서 폐기했다 —
  몸통 높이에서 옆으로 당긴다.
- 화살은 **무기 든 손**에서 나간다 (`muzzleSideMul` 0.85 × radius, `muzzleHeightMul`
  0.72 × height — Stage 의 팔 피벗과 같은 값).

## 3.4 피격 밀림과 이동

`balance.playerKnockback`. **밀림과 이동 입력은 서로를 막지 않고 더해진다** —
밀리는 동안에도 걸을 수 있다. 대신 그동안 이동 입력은 `moveSpeedMul`(0.5) 배로 눌린다.

창 찌르기(1.6m / 8틱) 기준 실측:

| 입력 | 뒤로 밀린 거리 |
|---|---|
| 없음 | 1.60m |
| 앞으로(밀림 반대) | 1.10m |
| 앞으로 질주 | 0.85m |
| 뒤로(밀림 방향) | 2.10m |
| 옆으로 | 1.60m + 옆 0.50m |

- **완전히 멈출 수는 없다.** 배율을 걸어도 달려들면 거리가 줄 뿐이다 (0.5 이전에는
  질주로 1.6 → 0.25 까지 상쇄돼 밀림이 거의 무의미했다).
- **방패로 막으면 다르다** — 격돌 경직(`block.clashPlayerStunTicks`) 동안 이동 입력이
  통째로 막히므로 밀림이 온전히 들어간다. 대신 밀림 자체가 `blockedMul`(0.33) 배다.
- **종류별 예외** `blockedMulByKind` — 던진 바위는 1.0 이라 방패로 받아도 그대로 민다
  (1.8m). 무게가 실린 물건은 막았다고 안 밀릴 수 없다.
- 회피 대시 중에도 같은 이유로 이동 입력이 막힌다.

## 3.5 스태미너

`balance.player.stamina`. 질주와 회피가 같은 통을 쓴다 — 도망칠 것인지 피할 것인지 고르게 한다.

| | 값 | 체감 |
|---|---|---|
| 최대 | 100 | |
| 질주 소모 | 0.35/틱 | 약 4.8초 연속 질주 |
| 회피 소모 | 15 | 가득 차면 6회 (7회째 차단) |
| 해머 1·2타 | 6 | |
| 해머 마무리 3타 | 12 | 3타 콤보 한 바퀴 = 24 → 약 4바퀴에 탈진 |
| 회복 | 0.7/틱, `regenDelayTicks`(45) 뒤부터 | 25→100 이 1.8초 |
| 탈진 중 회복 | **0.18/틱** | 0→25 만 2.3초 |
| 탈진 중 이동 | **×0.5** | 6.0 → 3.0 m/s |
| 탈진 해제선 | 25 | |

- **질주는 실제로 움직이는 동안만 닳는다.** 제자리에서 쉬프트만 쥐고 있으면 무소모.
- **바닥나면 탈진** — `exhaustRecoverTo`(25)까지 차야 다시 질주할 수 있다. 0에서 바로
  풀면 쉬프트를 톡톡 눌러 무한 질주가 된다.
- **탈진 구간은 대가가 확실하다** — 회복이 4배 가까이 느려지고(0.18 vs 0.7) 걸음도
  절반이 된다. 해제선을 넘는 순간 둘 다 원래대로. 방어 중이면 감속이 곱해진다(×0.5×0.35).
- **모자라면 회피가 아예 안 나간다** (`stamina_blocked`). 스태미너도 소모되지 않는다.
- **해머는 모자라도 막지 않는다.** 거미줄은 해머로만 걷어낼 수 있어(3회) 스윙을
  잠그면 탈진+거미줄에 갇힌다. 대신 0이 되면 탈진 규칙이 그대로 걸린다.
- 소모는 그 행동을 하는 시스템이 직접 한다 — 질주는 `PlayerMove`, 회피는 `Reaction`,
  해머는 `Weapons`.
  `Stamina` 시스템은 회복과 탈진 해제만 맡는다. 공용 감산은 `World.spendStamina`
  (`pushPlayer` 와 같은 규약 — balance 는 호출부가 읽어 넘긴다).

## 4. 연쇄 배율

```
chain 0 → ×1.0
chain 1 → ×1.4
chain 2 → ×1.8
chain 3+ → ×2.5   (각인 '연쇄 해방' 보유 시 계속 상승)
```

**증가** — 완벽 패링, 반사 성공
**유지** — 일반 패링 (증가하지 않음)
**리셋** — 피격, 패링 실패, 마법 시전

일반 패링이 배율을 올리지 않는 것이 핵심이다. 안전하게 막기만 해서는 대형 마법에 도달할 수 없다.

### 휘발

전투 종료 판정: **활성 적(플레이어를 인지한 적)이 0이 된 뒤 `mana.combatExitTicks` 경과.**

이후 매 틱 `mana.decayPerTick`씩 감소한다. 목표는 방을 나설 때 사실상 0이 되는 것.

전투 재진입 시 감소를 즉시 중단한다 (초기화는 하지 않음).

### 상한

기본 `mana.max`. 각인 '마력 심장' 보유 시 +60%.

`entities.json`의 `weapons` 항목에서 로드.

| 무기 | 발사 방식 | 특성 |
|---|---|---|
| 권총 (9mm) | 세미오토, 히트스캔 | **방어막 관통** — 유일 |
| 기관총 (5.56) | 풀오토, 히트스캔 | 부위 파괴, 군집 처리 |
| 수류탄 | 투척, 물리 없음(포물선 스크립트) | 균열벽 파괴 가능 |
| 섬광탄 | 투척 | 어둠 적응 생물 실명 + 강제 실체화 |

### 총구 화염 조명

발사 시 1~2틱 동안 점광원을 켠다. 강도는 랜턴의 3배, 반경은 랜턴의 절반.
**이것이 실질적인 정찰 수단**이므로 시각적으로 충분히 커야 한다. 미묘하게 만들지 말 것.

### 해머 3타 콤보와 적중 가속

`balance.weapons.hammer.combo`. **살을 때린 스윙에만** 가속이 붙는다 — 후딜
(`hitCooldownMul` 0.85)과 예비동작(`hitImpactMul` 0.9)이 함께 줄고, 뷰모델 스윙도
같은 배율(×1.11)로 빨라진다. 그림만 두면 해머가 닿는 순간과 판정 시점이 어긋난다.

**의도적으로 작다.** 0.6/0.7(−36%)과 0.65/0.75(−15%)를 차례로 넣어 봤는데 둘 다
근접 난이도가 무너졌다 — 원속도에서 "조금 빨라진 느낌"이 상한이다.

**연결 안에서만 산다.** 마무리 3타를 치면 다음은 다시 1타이므로 원속도로 돌아가고,
헛치거나 연결 창(`windowTicks`)이 닫혀도 끝난다. 방패에 튕긴 것은 적중이 아니다 —
감면 없이 `blockedRecoil` 만 더해진다.

| 전이 | 원속도 | 적중 연속 |
|---|---|---|
| 1타 → 2타 | 23틱 | **20틱** |
| 2타 → 3타 | 26틱 | **23틱** |
| 3타 → 1타 | 42틱 | 42틱 (감면 없음) |
| 3타 주기 | 91틱 (1.52초) | **85틱 (1.42초) — −6.6%** |

전부 헛치면 29·32·62 = 123틱으로 그대로다. 실측값이며 `Weapons.test.ts` 가 공식을 잠근다.

## 8. 계측 이벤트

`Reaction.ts`와 `Mana.ts`는 다음 이벤트를 반드시 발행한다.

```
parry_attempt   { result: 'perfect'|'normal'|'fail', chain, enemyType }
mana_gained     { amount, source, chain }
mana_decayed    { amount, wasted: boolean }
weapon_kill     { weapon, enemyType }
melee_kill      { enemyType }
```

`mana_decayed`의 누적이 곧 **마나 휘발률** 지표다. 이 값이 30%를 넘으면 코어 루프가 작동하지 않는다는 신호다.
